because their canonical producers are non-importable top-level scripts.

## Defects found and fixed during verification
1. **`population.derive_folds` bucket cursor was per-domain.** `sizes = [0]*n_outer` sat
   inside the domain loop, so a domain with fewer groups than `n_outer` only ever touched the
   first `groups_per_domain` buckets ⇒ folds 3/4 of the cv5 table had an EMPTY `outer_target`
   (silent mis-fold, not an error). Hoisted the cursor to be global and added a fail-fast
   check for under-grouped populations plus a post-build empty-role check.
   Symptom was `fold3 ... fit=16 es=8 ot=0` in the B stage.
2. **Router/safety cross-fit was inventing its inner split.** Replaced a
   `np.random.default_rng(...).permutation` early-stop split with the frozen Phase-25D
   FIT / EARLY_STOP / OUTER_TARGET membership table + explicit empty-role and overlap asserts.
3. **`Path.relative_to` raised for run roots outside the repo** (tests use temp dirs).
   Added `provenance.relpath_str()` and replaced every `relative_to(R.ROOT)` call.
4. **CUDA non-determinism** (~4e-7 divergence at epoch 1) — `cudnn.deterministic` alone is
   insufficient; added `torch.use_deterministic_algorithms(True, warn_only=False)` +
   `CUBLAS_WORKSPACE_CONFIG=:4096:8`.
5. **Test fixture bulk-deleted its run root** (~200 files) which tripped the harness
   bulk-delete guard and killed pytest mid-session (SystemExit inside fixture setup). Switched
   to a PID-unique root, no deletion. The pipeline treats an existing stage dir as COMPLETE,
   so a shared root would silently skip stages on the second run anyway.

## Load-bearing design decisions
- **Three adapter kinds, not flattened:** `ROUTED` (FULL/Lite, full G/R/B/S), `TASK_CONDITIONED`
  (GlobalMedFiLM), `PLAIN` (5 baselines, **no task input** — feeding one a task id would be a protocol
  change, not a fairness fix).
- **At init FiLM conditioning is an identity:** γ/β out-proj is zero-init ⇒ identical outputs across
  task ids is *expected*, NOT evidence the id is ignored. Test 2 therefore spies that the id **reaches**
  the network rather than comparing outputs.
- **No p-value is possible.** `compare_pair` returns `p_value=None`; `CONFIRMATORY_AUTHORIZED=False`;
  non-inferiority bound exposed only with an explicit `protocol_reference`.
- **Synthetic never completes a cell:** `research_cells_completed` = 0 unconditionally; evidence
  `SYNTHETIC_TEST_ONLY`; `RESEARCH_EVIDENCE_CLASSES = {REAL_VAL808_DEVELOPMENT}`.

## FOUR REAL DEFECTS FOUND BY THE NEW TESTS (all fixed)
1. **Resume could not publish.** `evaluate_cell(resume=True)` returned only the newly-scored records, so
   `publish_cell` hit a roster mismatch. Ledger now stores the **whole record**; resume merges prior
   records in roster order and re-checks the roster. A legacy identity-only line now raises instead of
   silently dropping images.
2. **A fresh pass wrote no ledger** ⇒ an interrupted *first* run had nothing to resume from. Ledger is now
   written on every pass; `resume` only controls whether prior entries are honoured; a fresh pass resets it.
3. **`verify_cell` omitted `document` for a MISSING cell** ⇒ `collect_results` raised `KeyError` on any
   partial root. `document` is now always present.
4. **Latency and memory shared a bare `unit` key** ⇒ a dict merge let `"MiB"` overwrite
   `"milliseconds per image"`. `profile_cell` now builds fields explicitly with `latency_unit` /
   `memory_unit` / `macs_unit`.
Plus: `RoutedAdapter` with no run root raised a bare `TypeError`; now `AdapterUnavailable`.
`evaluate_non_inferiority` gained `protocol_reference=""` so the explicit refusal fires instead of TypeError.
`paired`/`failures` tables now carry `evidence_class`; empty root banner is `NO_EVIDENCE` (was `MIXED`).

## Torn-append semantics (verified, worth remembering)
A torn ledger line **with** a trailing newline loses only itself. A torn line **without** a newline
swallows the next appended record; the next resume re-scores exactly that one sample and still publishes a
complete roster. Never a silent gap.
