# RA-MedFiLM-BARR Git Commit and Push Policy

Applies after every completed coding-agent task. This rule grants no scientific execution permission.

1. Verify actual task completion with targeted tests and artifact read-back. Inspect current branch, HEAD, index and relevant working-tree state before writes. If unrelated changes are staged, stop without modifying that index.
2. Identify exact task-owned paths. Preserve unrelated tracked/untracked/ignored work and frozen scientific artifacts. Record/check authoritative hashes and scientific preservation where applicable.
3. Screen intended files and staged blobs for secrets, personal/patient data, restricted datasets, large checkpoints, caches and temporary authorization records. Never commit those. Ignored documentation may be force-added only by exact approved path; never remove the reports ignore rule casually.
4. Stage exact intended paths only. Never indiscriminately use git add -A or git add . . Review staged name set, diff, stat and whitespace check; exclude every pre-existing unrelated modification.
5. Use existing legitimate commit identity and a clear task-specific message. Do not amend frozen commits, rewrite history, reset/delete unrelated changes, change branches, force-push, or automatically merge/rebase a rejected push. Never silently disable hooks/security checks. Disclose and obtain permission for any necessary override; avoid opaque side effects.
6. Push only to an already verified, operator-authorized GitHub remote and intended upstream. Private by default; public release needs explicit approval. Before an initial push review the full outgoing history, not just latest files, for credentials, patient information, restricted manifests/data and binaries. Do not read protected scientific data merely to complete a Git audit; escalate disclosure review instead. A configured URL alone is not release approval. Do not expose/change credentials.
7. If no remote: do not invent/configure one; retain the successful scoped local commit and report GIT_REMOTE_CONFIGURATION_REQUIRED and PUSH_BLOCKED. If authentication/network/push rejection occurs, preserve local commit and report BLOCKED, not silent omission. Never claim remote verification if none occurred.
8. When allowed, push without force; verify the remote branch SHA equals the intended commit and report remote identity/branch without credentials. No repository changes means no empty commit/push unless previously committed work has explicit upload approval.
9. Final task report must include GIT_COMMIT_SHA, GIT_REMOTE, GIT_PUSH_STATUS (PUSHED/BLOCKED/NO_CHANGES), SCIENTIFIC_EXECUTION_STATUS. Never claim commit/push success without its verified SHA.

Git maintenance must not train, infer on real data, open TEST/ROUTER_HOLDOUT, activate C1, fabricate authorization, or modify BARR-M1 RC1. C1 approval is separate from BARR-M1. New implementation can be synthetic-tested while scientific execution stays blocked. Preserve additive versioned documentation; do not edit frozen records to make checks pass.
